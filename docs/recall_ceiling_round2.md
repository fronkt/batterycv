# Recall ceiling, round 2: the ceiling is mostly the ruler

**Verdict (2026-08-06).** The documented ~0.45 recall ceiling is substantially an artifact of the
eval set's box geometry, not a limit of the imagery. The detector is finding the batteries. The
lighting recommendation in `recall_ceiling_findings.md` is **withdrawn pending a re-labeled eval
set**, and no recall number from this project should be quoted until that relabeling is done.

This document supersedes the *conclusions* of `recall_ceiling_findings.md`. It does not dispute
its experiments — the labeler swaps, resolution sweeps and fine-tune plateau all reproduce. Every
one of them was measured against the same ruler, which is why they all hit the same wall.

---

## How this was measured

All Phase-4 numbers come from one matcher, `batterycv/evalutil.py`, gated before use against the
published ft1 result (`scripts/validate_harness.py`):

| | this harness | published (Ultralytics `model.val`) |
|---|---|---|
| recall @ conf 0.25 | 0.452 | 0.446 |
| AP@0.5 / mAP50 | 0.233 | 0.252 |

Per-class recall reproduces the documented pattern exactly (ni_mh_all 0.08, li_ion_mobile 0.41).
Precision reads lower (0.410 vs 0.466) only because Ultralytics reports P at best-F1 rather than
at a fixed confidence.

An adversarial review of the matcher (see "Matcher audit" below) bounded its divergence from the
original `probe_labeler.match` at **+0.0013 to +0.0019 recall** over 40,000 randomized frames, and
showed only 5 of the 323 same-frame GT pairs in this eval set can even admit a disagreement. The
Phase-4 numbers and the published tables are comparable.

## Finding 1 — only 5.9% of ground-truth batteries are actually undetected

`scripts/analyze_misses.py`, ft1 accept-all, 186 GT boxes:

| outcome | share | what it means |
|---|---|---|
| covered (IoU >= 0.5) | 48.9% | |
| **near-miss (0.3 <= IoU < 0.5)** | **32.8%** | object IS proposed, box disagrees |
| partial (0.1 <= IoU < 0.3) | 12.4% | |
| **total miss (IoU < 0.1)** | **5.9%** | genuinely nothing proposed |

Recall would be **0.817** if every near-miss were nudged over the bar. The binding constraint is
box geometry, not detectability.

## Finding 2 — the metric is extraordinarily threshold-sensitive

`scripts/probe_gt_audit.py`, conf >= 0.25:

| class | IoU 0.3 | IoU 0.5 | centre-in-GT |
|---|---|---|---|
| li_ion_laptop | 0.933 | 0.733 | 0.933 |
| li_ion_mobile | 0.855 | 0.406 | 0.884 |
| liso2 | 0.826 | 0.435 | 0.913 |
| ni_cd_bulk | 0.938 | 0.750 | 0.875 |
| ni_cd_small | 0.652 | 0.435 | 0.783 |
| ni_mh_all | 0.440 | 0.080 | 0.560 |
| **TOTAL** | **0.790** | **0.452** | **0.839** |

"Centre-in-GT" asks the convention-free question — did a detection land *on* the object — and
answers 0.839. Every class shows a 15–48 point gap between it and IoU-0.5 recall. That gap is the
signature of a localization/convention disagreement, not of missing objects.

## Finding 3 — blind human-style audit says the GT box is the wrong one

Three independent auditors judged 36 near-miss panels **without being told which box source was
which** (`docs/figures/phase4_nearmiss_*.png`, generated by `probe_gt_audit.py`):

- **34 of 36 panels** favoured the detector's box by majority; 1 favoured GT; 1 ambiguous.
- 33 of 36 panels (91.7%) unanimous. Sign test p ≈ 2e-9. Wilson 95% CI on the detector's win
  rate among decisive panels [0.855, 0.995].
- Failure mode they converged on independently: the GT box is larger than the object, translated
  down and/or left, biased toward a square aspect regardless of object shape, sometimes spanning
  two or three separate cells.

**Visibility, the load-bearing question for the lighting ask:** of 108 ratings, **96 "obvious",
12 "subtle", 0 "invisible"**. `recall_ceiling_findings.md` states "ni_mh is essentially invisible
(<=0.08 everywhere)". Ten audited panels were ni_mh_all; **all 30 ratings were "obvious" and all
30 favoured the detector**. Blind auditors described them as "pale-green cylindrical cells,
instantly findable". The 12 "subtle" ratings were attributed to crop geometry (thin slivers,
extreme zoom), not illumination; only 2 of 36 panels were genuinely contrast-limited, and the
detector found both.

## Finding 4 — contrast is ANTI-correlated with recall

Object-vs-belt contrast measured inside **tight detector boxes** on raw (lossless) frames, in
units of the measured per-pixel temporal noise (σ ≈ 5.3 grey levels):

| class | median contrast | σ | recall @0.5 |
|---|---|---|---|
| ni_cd_small | 56.5 | **10.7** | 0.435 |
| ni_mh_all | 34.9 | **6.6** | **0.080** |
| li_ion_laptop | 16.7 | 3.2 | 0.733 |
| li_ion_mobile | 15.9 | 3.0 | 0.406 |
| liso2 | 15.2 | 2.9 | 0.435 |
| ni_cd_bulk | 11.3 | **2.1** | **0.875** |

The two highest-contrast classes have the worst recall; the two lowest-contrast classes have the
best. If low contrast caused the ceiling this would run the other way. One plot would have
falsified the darkness story before the hardware ask was drafted.

Note the same statistic measured inside the *loose GT boxes* reads only 11–18 grey levels — a loose
box dilutes any appearance statistic computed from it, which is likely how the darkness story
survived scrutiny.

## What this does NOT show

Stated explicitly, because the temptation to over-read it is strong:

1. **No corrected recall number exists.** Nobody re-drew a box. Any restated performance figure
   would be fabricated. The honest position is "we do not have a trustworthy recall number".
2. **The ground truth is not shown to be globally bad.** Only the *disputed* band was audited. The
   91 GT boxes already at IoU >= 0.5 (49% of the set) were never examined and may be fine.
3. **Lighting is not shown to be irrelevant.** The audit is structurally blind to the 11 total
   misses (IoU < 0.1) — they produce no panel, because there is no detector box to draw. That
   population is exactly where "too dark to detect" could still be true, and ni_mh_all has a 24%
   total-miss rate. The supported claim is narrower: lighting cannot explain the *bulk* of the
   gap, so it is not justified as the *primary* fix.
4. **The GT failure mechanism is not diagnosed.** "Translated down-left, square-aspect-biased" is
   three auditors' visual impression. No offset vector has been measured. Promoting that to a root
   cause before measuring it would repeat precisely the error this document is correcting.
5. **The detector is not vindicated in general.** Auditors also faulted it for touching
   neighbouring objects and, in the dense laptop frames, merging two adjacent packs into one box.

Sample bounds: 36 panels drawn from the 89 near-miss cases (~40%), i.e. 19% of the eval set, and
selected *because* they are disagreements. "One source is usually wrong" was selected for; the
finding that survives is *which* source, and in which direction.

## Negative results from this round (both clean, both worth not repeating)

**Global box-scale correction — fails.** If the near-misses were a systematic geometric bias, a
fitted scale factor would recover recall for free. In-sample the best isotropic scale (1.10) gains
+0.006. Fitted on one half of the frames and scored on the other: **−0.011 and −0.053**. It was
fitting noise. The per-class width ratios explain why — the bias is not even consistent in
direction (liso2 1.33 oversized, ni_mh_all 0.80 undersized). `scripts/probe_boxscale.py`.

**Temporal stacking and flat-fielding — fail.** In belt-aligned coordinates the scene is static,
so averaging aligned neighbours should denoise at √k. Noise did fall as predicted (k=2: 0.74 vs
0.71 theory), but noise-corrected object edge energy fell just as fast, so object-edge SNR never
improved (×0.97 at k=2, ×0.66 at k=8). Cause: 13 px median residual misregistration (~7% of a
179 px object), and it is not an interpolation artifact — nearest-neighbour at integer shift
(0.59) and cubic (0.61) barely differ from bilinear (0.55) against the ~1.00 needed. A2
flat-fielding corrects a real 1.89× centre/corner vignette but lowers recall, plausibly because
CLAHE at grid=8 already equalizes locally. **All 10 temporal variants covered zero GT objects the
baseline misses.** `scripts/probe_temporal.py`.

**Inference resolution and tiling — no new objects; tiling actively loses some.** Every inference
had been downscaling the 1280x1024 frames to imgsz 1024, and object size predicts failure
(covered objects median min-side 184 px, total misses 128 px), so both native-resolution and
tiled inference on the frozen ft1 looked promising. Neither delivers:

| config | recall@0.5 | prec@0.5 | recall@0.3 | centre-in-GT |
|---|---|---|---|---|
| imgsz 1024 (baseline) | 0.452 | 0.410 | 0.790 | 0.839 |
| imgsz 1280 (native) | 0.457 | 0.411 | **0.790** | **0.839** |
| 2x2 tiling @1024 | 0.446 | 0.472 | 0.742 | **0.758** |

Native resolution moves the two convention-free columns by **exactly nothing** — it finds no
object it was not already finding, it only tightens boxes fractionally. Tiling trades recall for
precision (+0.062 precision) and makes the convention-free columns *worse*: centre-in drops 8
points, i.e. it genuinely loses objects, most plausibly the large laptop/bulk packs that straddle
a tile seam or overflow a tile's field of view (ni_cd_bulk 0.750 → 0.688, ni_mh_all 0.080 →
0.040, while the small-cell class ni_cd_small does improve 0.435 → 0.478).

That both fail is consistent with everything else here: the objects are not too small or too
poorly resolved to detect, because they are already being detected.
`scripts/probe_inference_scale.py` (use `--only` to run one config at a time; tiling is 4-9x the
cost of a plain pass).

## Belt physics, re-verified (and one correction to this round's own work)

Objects **ride the belt and translate with it** — pure horizontal, ~100–150 px/frame, per-run
speed varying ~30–220. Verified by detected-centroid displacement (run 92: x = 1212→1070→919→764).
The `lessons.md` figure of ~156 px/frame is **confirmed**, and BoT-SORT's rationale stands.

A trap worth recording: brute-force searching the shift that minimises **whole-frame** mean
absolute difference returns ~0 and is flatly wrong — the belt is near-featureless and objects
cover a tiny area fraction, so that average is insensitive to the true shift. It briefly produced
a confident "the belt is static, the 156 px figure is an artifact" conclusion that the centroid
check demolished. Estimate shift on high-gradient pixels or by phase correlation, and validate
against object displacement. (Also: dy is not 0, it is ~+2 to +4 px/frame.)

## Matcher audit

`batterycv/evalutil.py` was adversarially reviewed. AP@0.5 verified exact against a from-scratch
reference over 4,000 random curves (max diff 4.4e-16). Bugs found and fixed:

- per-class `box/f` divided by total frames instead of that class's frames (6× understated)
- `ap50()` silently deflated when scored and score-less frames are mixed — now returns NaN
- `scores`/`boxes` length mismatch silently deflated recall — now raises
- an (N,5) xyxy+conf array silently reshaped into garbage when 5N % 4 == 0 — now raises
- reading `recall("unseen_class")` inserted a phantom all-zero class row
- `coverage()` matched in input order, so union/complementarity could under-count; now an optimal
  (Hungarian) maximum matching, since coverage is a ceiling and must not depend on array order

None of these affect the recall/precision conclusions above; the per-class `box/f` column was the
only published-number-facing defect, and it appears nowhere in this document's tables.

## What to do next

1. **Re-label the 72-frame eval set to a written box convention** — by a human. This is the
   highest-value action in the project and everything else is blocked behind it. The convention
   must state at minimum: does an attached wire/connector belong inside the box (the single most
   common disagreement seen); how are touching/overlapping cells separated; how are objects
   clipped by the frame edge handled. `scripts/label_assisted.py` already pre-fills detector boxes,
   which is now known to be a *good* starting point rather than a biased one.
2. **Then re-measure everything.** Detector comparisons in `recall_ceiling_findings.md` were all
   made against the old ruler. Their *ordering* is probably still roughly right (same bias applied
   to all), but the absolute numbers and the "ceiling" framing are not trustworthy.
3. **Only then** revisit hardware. The residual 5.9% total-miss population is the only evidence
   that could support a lighting change, and it needs to be re-examined on corrected labels first.
4. Deferred, still untested, and cheap once the ruler is fixed: multi-checkpoint fusion
   (`scripts/probe_ensemble.py`), preprocessing sweep (`scripts/probe_preprocess.py`),
   inference-resolution and tiling (`scripts/probe_inference_scale.py`). All are built and smoke-
   tested. Running them to three decimals against the current labels would repeat the round-1
   mistake of optimizing against a broken metric.

python scripts/analyze_misses.py                   # miss taxonomy + photometry
python scripts/probe_gt_audit.py                   # IoU sweep, centre-in, near-miss contact sheets

python scripts/probe_temporal.py                   # the temporal negatives (~1 h CPU)
